MCP入門：Model Context Protocolの歴史と仕組み

MCP（Model Context Protocol）は、AIアプリケーションを外部のデータやツールにつなぐ共通規格です。生まれた理由、2024年の公開から2026-07-28版までの経緯、基本の仕組みを説明します。

MCP（Model Context Protocol）は、AIアプリケーションを外部のデータやツールにつなぐための共通規格です。2024年11月に公開され、現在はChatGPT、Claude、Visual Studio Code、Cursorなどが対応しています。

この記事では、MCPが生まれた理由、公開から現在までの経緯、基本の仕組みを順に説明します。プログラミングの知識がなくても読めるように書いています。JSONの例が2つ出てきますが、読み飛ばしても内容は理解できます。

MCPとは

MCPは、ChatGPTやClaudeなどのAIアプリケーションに、外部のサービスをつなぐためのオープンな規格です。ブラウザは、プラグインを追加すると機能が増えます。AIアプリケーションも同じです。MCPサーバーをつなぐと、AIが扱えるデータと実行できる操作が増えます。

たとえば、次のようなことができます。

  • 会計サービスの仕訳データをAIに読ませて、月次の集計を作る
  • 社内のデータベースに、チャットから問い合わせる
  • カレンダーの予定を確認して、会議の候補日を出す

公式ドキュメントは、MCPを「AIアプリケーションのためのUSB-Cポート」と説明しています。USB-Cが機器の接続方法を1つにそろえたように、MCPはAIアプリケーションと外部システムの接続方法を1つにそろえます。

MCPが生まれた理由

大規模言語モデル（LLM）は、学習したデータの範囲でしか答えられません。今日の売上も、社内の文書も、モデルの中にはありません。実務で使うには、モデルを外部のデータやツールにつなぐ必要があります。

MCPの公開前は、この接続をアプリケーションごと、サービスごとに個別に開発していました。AIアプリケーションが5種類、つなぎたいサービスが20種類あれば、最大で100通りの接続を開発することになります。片方の仕様が変わるたびに、接続の修正も必要でした。

Anthropicは公開時の発表で、この状況を次のように説明しています。

どれほど高度なモデルも、データから切り離されているという制約を受けています。データは、情報のサイロや古いシステムの中に閉じ込められています。新しいデータソースをつなぐたびに個別の実装が必要になり、つながったシステムを広げていくことが難しくなっています。（mcpnaviによる訳）

MCPは、この接続を1つの規格にまとめます。サービスの提供元はMCPサーバーを1つ公開します。AIアプリケーションの開発元はMCPクライアントを1つ実装します。それだけで、どの組み合わせでも接続できます。先ほどの例なら、開発するものは100通りの接続から、5つのクライアントと20のサーバーに減ります。

この考え方には手本があります。MCPの仕様書は、Language Server Protocol（LSP）から着想を得たと書いています。LSPは、プログラミング言語の対応をエディタごとに開発しなくて済むようにした規格です。MCPは同じ方法を、AIアプリケーションとツールの接続に当てはめました。

MCPの歴史

公開から現在までの主な出来事は、次のとおりです。仕様の版は、互換性のない変更が最後に入った日付で呼びます。

日付 出来事
2024-11-25 AnthropicがMCPをオープンソースとして公開
2025-03-26 仕様2025-03-26版を公開。同日、OpenAIが対応を発表
2025-04-09 Google DeepMindが、GeminiのMCP対応を表明
2025-05-19 MicrosoftとGitHubが、MCPの運営委員会に参加
2025-06-18 仕様2025-06-18版を公開
2025-09 公式のMCP Registryを発表
2025-11-25 公開1周年。仕様2025-11-25版を公開
2025-12-09 AnthropicがMCPをLinux Foundation傘下の財団に寄贈
2026-07-28 仕様2026-07-28版を公開。プロトコルがステートレスになる

2024年：公開

2024年11月25日、AnthropicがMCPをオープンソースとして公開しました。公開したものは、仕様とSDK、Claude Desktopのローカルサーバー対応、サーバーの実装を集めたリポジトリの3つです。Google Drive、Slack、GitHub、Git、Postgres、Puppeteerのサーバーが最初から用意されていました。初期の導入企業としてBlockとApolloが、開発ツールではZed、Replit、Codeium、Sourcegraphが名前を連ねています。

このときClaude Desktopが対応したのは、手元のPCで動かすローカルのサーバーでした。

2025年：各社の対応と、リモート接続

2025年3月26日の仕様改定で、2つの大きな機能が入りました。1つは、インターネット越しの接続に使うStreamable HTTPです。もう1つは、OAuth 2.1にもとづく認可の枠組みです。この2つによって、提供元が運用するサーバーにURLだけで接続する「リモートMCPサーバー」が現実的になりました。

同じ3月26日、OpenAIがMCPへの対応を発表しました。まずAgents SDKが対応し、ChatGPTのデスクトップアプリとResponses APIが続くという内容です。競合する会社が作った規格を採用したことで、MCPは1社の規格から業界の共通規格へと位置づけが変わりました。4月9日にはGoogle DeepMindのCEOが、GeminiのモデルとSDKをMCPに対応させると表明しました。5月19日にはMicrosoftとGitHubが、開発者会議BuildでMCPの運営委員会への参加を発表しました。

6月18日の仕様改定では、ツールが構造化データを返せるようになりました。サーバーが利用者に追加の入力を求める機能（エリシテーション）も加わりました。9月には公式のMCP Registryが発表されました。公開されているMCPサーバーを登録し、探すための台帳です。11月の時点で、2,000件近くが登録されています。

11月25日、公開1周年に合わせて仕様2025-11-25版が公開されました。時間のかかる処理を扱うタスク機能が実験的に入り、核となる仕様の外に機能を足す「拡張」の枠組みもできました。

12月9日、AnthropicはMCPをAgentic AI Foundation（AAIF）に寄贈しました。AAIFはLinux Foundationの傘下に新設された財団で、Anthropic、Block、OpenAIの3社が共同で設立しました。Google、Microsoft、AWS、Cloudflare、Bloombergも支援しています。Anthropicはこのとき、2つの数字を発表しています。公開されているMCPサーバーは1万以上です。PythonとTypeScriptのSDKは、月に9,700万回以上ダウンロードされています。MCPは特定の会社のものではなく、中立な団体が管理する規格になりました。

2026年：ステートレス化

2026年7月28日に公開された2026-07-28版は、リモート接続が入って以来もっとも大きな改定です。プロトコルが「ステートレス」になりました。内容は「2026-07-28版で変わったこと」の節で説明します。

公式ブログによると、主要なSDKのダウンロード数は月に5億回近くに達しています。

基本の仕組み

3つの登場人物

MCPには、ホスト、クライアント、サーバーの3つが登場します。

名前 役割 例
ホスト 利用者が使うAIアプリケーション Claude Desktop、Visual Studio Code
クライアント ホストの中にあり、サーバー1つとの接続を受け持つ部品 ホストが内部に持つ
サーバー データやツールを提供するプログラム 会計サービスのMCPサーバー

ホストは、接続するサーバーごとにクライアントを1つ作ります。サーバーを3つつなげば、ホストの中にクライアントが3つできます。利用者から見えるのはホストとサーバーだけで、クライアントを意識することはありません。

サーバーが提供する3つのもの

サーバーがAIアプリケーションに提供できるものは、3種類あります。

種類 内容 例
ツール（Tools） AIモデルが実行できる関数 請求書を検索する、予定を登録する
リソース（Resources） AIに読ませるデータ ファイルの内容、データベースの定義
プロンプト（Prompts） 定型の指示文 「この月の経費を要約する」という手順

mcpnaviは、このうちツールを「提供ツール」の項目として、サービスごとに掲載しています。

2つの接続方式

クライアントとサーバーのつなぎ方は、2つあります。

  • stdio：サーバーを手元のPCで動かし、標準入出力でやり取りします。ネットワークを通りません。利用者がサーバーを自分でインストールします。
  • Streamable HTTP：HTTPでやり取りします。提供元が運用するサーバーに、インターネット越しに接続できます。認可にはOAuthを使うことが推奨されています。

接続方式は、通信の形式を決めるだけです。Streamable HTTPのサーバーを、利用者が自分の環境で動かすこともできます。「サーバーを誰が運用するか」は別の情報です。mcpnaviは、前者を「接続方式」、後者を「提供形態」として、分けて掲載しています。

やり取りの中身

クライアントとサーバーは、JSON-RPC 2.0という形式のメッセージをやり取りします。流れは単純です。

  1. クライアントがtools/listを送り、サーバーが持つツールの一覧を受け取ります。
  2. ホストが、ツールの一覧をAIモデルに渡します。
  3. 利用者の依頼に応じて、AIモデルが使うツールを選びます。
  4. クライアントがtools/callを送り、サーバーがツールを実行して結果を返します。
  5. AIモデルが、結果を使って回答を作ります。

天気を調べるツールを呼び出す場合、クライアントは次のようなメッセージを送ります（一部を省略しています）。

{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "weather_current",
    "arguments": { "location": "Tokyo", "units": "metric" }
  }
}

サーバーは、結果を次のように返します。

{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "resultType": "complete",
    "content": [{ "type": "text", "text": "東京の現在の天気：24℃、晴れ" }]
  }
}

ツールの一覧には、ツールごとの名前、説明、引数の定義（JSON Schema）が入っています。AIモデルはこの説明を読んで、どのツールをいつ使うかを決めます。人が読むためのAPIドキュメントと違い、ツールの説明はAIモデルが直接読みます。

2026-07-28版で変わったこと

2025年までの仕様では、クライアントは最初にinitializeというメッセージをサーバーに送り、接続を確立していました。サーバーは、接続ごとの状態（セッション）を保持していました。

2026-07-28版は、この手順をなくしました。クライアントは、使う仕様の版と自分の機能を、リクエストのたびに送ります。サーバーは、リクエストを1つずつ独立して処理します。サーバーが対応する版と機能は、server/discoverで確認できます。

この変更で、提供元はサーバーを運用しやすくなります。セッションを保持しないサーバーは、一般的なロードバランサーの後ろに何台でも並べられます。公式ブログは、サーバーの信頼性と拡張性を求める開発者の声に応えた変更だと説明しています。

ツール、リソース、プロンプトの考え方は変わっていません。仕様書には、2025-11-25版以前のサーバーやクライアントと接続するための手順も書かれています。Roots、Sampling、Loggingなどの一部の機能は「非推奨」になりました。非推奨の機能は仕様書に残りますが、2027-07-28以降に公開される版から削除の対象になります。

利用前に確認すること

MCPサーバーをつなぐと、AIはデータを読み、操作を実行できるようになります。仕様書は、実装する側に次の原則を求めています。

  • 利用者の同意と制御：データへのアクセスと操作について、利用者が内容を理解し、同意していること
  • データのプライバシー：利用者の同意なしに、ホストがデータをサーバーに渡さないこと
  • ツールの扱い：ツールは任意のコードを実行できるものとして、慎重に扱うこと。ツールを呼び出す前に、利用者の同意を得ること

仕様書は同時に、プロトコルの側でこの原則を強制することはできないとも書いています。どのサーバーをつなぐかは、利用者が判断します。

判断の材料になる情報は、次のとおりです。

  • 誰が提供しているか（提供元、種別、国内法人の有無）
  • サーバーを誰が運用するか（提供形態）
  • どのように認証するか（認証方式）
  • どのツールを提供しているか（提供ツール）
  • 最後にいつ更新されたか（最終更新日）

mcpnaviは、これらの項目をサービスごとに公開ページから読み取り、情報確認日とともに掲載しています。読み取れなかった項目は「不明」と表示します。各項目の意味と確認方法は、掲載されているデータについてで説明しています。

まとめ

  • MCPは、AIアプリケーションと外部のデータやツールをつなぐ共通規格です。
  • 2024年11月にAnthropicが公開し、2025年にOpenAI、Google、Microsoftが対応しました。2025年12月からは、Linux Foundation傘下の財団が管理しています。
  • ホスト、クライアント、サーバーの3つが登場し、サーバーはツール、リソース、プロンプトを提供します。
  • 接続方式はstdioとStreamable HTTPの2つです。
  • 2026-07-28版でプロトコルがステートレスになり、サーバーを運用しやすくなりました。

MCPサービスを探すには、MCPサービス一覧を使います。URLだけで接続できるサービスは、この絞り込みで確認できます。

リモートMCPサーバーとローカルMCPサーバーの違い

リモートMCPサーバーは提供元が動かし、URLで接続します。ローカルMCPサーバーは利用者が手元のPCで動かします。提供形態と接続方式の違い、利用者がすること、認証情報の扱いを説明します。
