Japanese law MCP servers: 24 services that fetch statutes from the e-Gov Law API

A Japanese law MCP server lets an AI agent fetch the text of Japanese laws. Most call the Digital Agency's e-Gov Law API. This article explains the API and the 24 servers listed on mcpnavi.

I Iqbal Abdullah

A Japanese law MCP server is a plugin that lets an AI agent search Japanese laws and fetch their articles. Most call the e-Gov Law API, published by Japan's Digital Agency. The AI then answers with text fetched from official data, rather than writing from memory.

On 2 October 2026, mcpnavi lists 24 Japanese law MCP servers. This article explains how the e-Gov Law API works, then groups the 24 servers into general law and single subjects and gives the hosting, transport and data of each. For MCP itself, read the introduction to MCP.

What a law MCP server does

When you connect a law MCP server to an AI application, the AI can fetch legal data during a conversation. For example, when you ask for Article 32 of the Labor Standards Act, the AI calls a tool on the server. The server queries the e-Gov Law API and returns that article.

Servers differ in what they return. Some search by law name, some return one article at a time, and some return a whole law. Some return amendment history or the text of an article as it stood on a given date. Some also return data from outside e-Gov, such as the circulars (通達) of the National Tax Agency or the Ministry of Health, Labour and Welfare.

The e-Gov Law API

The e-Gov Law API lets a program fetch the legal data that e-Gov Law Search (e-Gov法令検索) publishes. The Digital Agency runs it.

What Version 2 added

The Digital Agency released Law API Version 2 on 14 March 2025. According to the release notice, Version 2 adds two features to Version 1: searching as of a given date, and fetching the text of an article as of that date. It also adds a search for repealed laws and a download of a law's full text as a file. Version 1 remains available for now.

The API covers data from 1 April 2017 onwards.

The six APIs

The specification (Version 2.1.139) defines six APIs.

API What it returns
Law list The laws that match the given conditions
Revision list The amendment history of one law
Law data The text of a law
Attachment A file attached to a law, such as an image
Keyword search The articles that contain a given phrase
Law file The text of a law as a file

Most of the APIs take a value called asof, which sets the date of the law. Without it, the API uses the law as it stands today. This lets a law MCP server return an article as it stood on a given day.

The data format is XML following the standard legal XML schema. The API can also return JSON, but the specification marks JSON as a trial version that may change.

The specification defines no authentication — not even an API key.

The law MCP servers on mcpnavi

mcpnavi tags services that work with Japanese law as law. The 24 servers break down as follows.

  • Transport: 22 support stdio only. 2 support Streamable HTTP.
  • Hosting: all 22 stdio servers are "Run it yourself". Of the 2 Streamable HTTP servers, 1 is "Connect by URL" and 1 is "Unknown".
  • Authentication: all 24 are "None".
  • Provider type: 21 individuals, 2 companies and 1 open-source project.

You run a "Run it yourself" server as a program on your own computer. Remote and local MCP servers explains the difference.

What to check when you choose a server

Hosting and transport

22 of the 24 servers are stdio servers that you run yourself. You set up the program by following the provider's steps and register the command that starts it in your client's settings. A client that cannot start a program cannot use such a server.

To connect by URL only, look for a service whose hosting includes "Connect by URL". The list of services you can connect to by URL shows them.

What the server returns, and how much

Check whether the server returns one article at a time or a whole law. Servers also differ in whether they return amendment history or the text as of a given date. Check whether the server works with data other than laws, such as circulars, court cases or enforcement cases. Each service's description is on its mcpnavi page and in its repository's README.

Last checked

Every value on mcpnavi was read from a public page. Each service's page shows the date its values were checked as "Last checked". About the data explains what each value means and how it is checked.

Before you rely on the answers

Compare any article in the AI's answer with the original text on e-Gov Law Search. Even when the server fetches the right article, the AI may change the wording when it summarises or quotes it.

The JSON format of the e-Gov Law API is a trial version. If its specification changes, a server that uses JSON can stop working. Check the date of the last update in the server's repository.

A server whose authentication is "None" still does not change where your question goes: the AI application you use receives it. Before you ask a question that contains business information, check how the AI application handles it. Authentication for MCP servers explains how servers and authentication fit together.

Summary

  • A Japanese law MCP server is a plugin that lets an AI agent search Japanese laws and fetch their articles.
  • Most of them use the Digital Agency's e-Gov Law API. Version 2 was released on 14 March 2025, returns articles as of a given date, and defines no authentication.
  • mcpnavi lists 24 such servers. 22 are stdio servers that you run yourself, and all 24 have the authentication "None".
  • 14 servers cover law in general. 10 focus on one subject, such as tax, labour, finance or building. Many of the single-subject servers also return data from outside e-Gov, such as circulars.
  • Check every article against the original text on e-Gov Law Search before you use it.
