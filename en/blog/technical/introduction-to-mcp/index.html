Introduction to MCP: the history of the Model Context Protocol and how it works

MCP (Model Context Protocol) is a common standard that connects AI applications to outside data and tools. This article covers why it was created, its history from 2024 to specification 2026-07-28, and how it works.

I Iqbal Abdullah

MCP (Model Context Protocol) is a common standard for connecting AI applications to outside data and tools. It was published in November 2024. ChatGPT, Claude, Visual Studio Code, Cursor and others support it today.

This article explains why MCP was created, what has happened since its release, and how it works. You do not need to know how to program. Two JSON examples appear; you can skip them and still follow the article.

What MCP is

MCP is an open standard for connecting outside services to AI applications such as ChatGPT and Claude. A browser gains features when you add a plugin. In the same way, an AI application that connects to an MCP server gains data it can read and actions it can take.

For example:

  • The AI reads journal entries from an accounting service and builds a monthly summary.
  • You query a company database from a chat window.
  • The AI checks a calendar and proposes dates for a meeting.

The official documentation describes MCP as "a USB-C port for AI applications". USB-C gave devices one way to connect. MCP gives AI applications and outside systems one way to connect.

Why MCP was created

A large language model (LLM) can only answer from the data it was trained on. Today's sales figures are not in the model. Neither are your company's documents. To be useful at work, a model needs a connection to outside data and tools.

Before MCP, each connection was built separately, for each application and each service. With 5 AI applications and 20 services, that is up to 100 connections to build. Each one needed a fix whenever either side changed.

Anthropic described the situation in its launch announcement:

Even the most sophisticated models are constrained by their isolation from data—trapped behind information silos and legacy systems. Every new data source requires its own custom implementation, making truly connected systems difficult to scale.

MCP turns those connections into one standard. A service provider publishes one MCP server. An AI application developer builds one MCP client. After that, any combination can connect. In the example above, the work drops from 100 connections to 5 clients and 20 servers.

The idea has a model. The MCP specification says it takes inspiration from the Language Server Protocol (LSP). LSP removed the need to build support for each programming language in each editor. MCP applies the same approach to AI applications and tools.

The history of MCP

These are the main events from the release until now. A specification revision is named by the date of its last backwards-incompatible change.

Date Event
2024-11-25 Anthropic publishes MCP as open source
2025-03-26 Specification 2025-03-26 is published. OpenAI announces support the same day
2025-04-09 Google DeepMind says Gemini will support MCP
2025-05-19 Microsoft and GitHub join the MCP steering committee
2025-06-18 Specification 2025-06-18 is published
2025-09 The official MCP Registry is announced
2025-11-25 First anniversary. Specification 2025-11-25 is published
2025-12-09 Anthropic donates MCP to a foundation under the Linux Foundation
2026-07-28 Specification 2026-07-28 is published. The protocol becomes stateless

2024: the release

On November 25, 2024, Anthropic published MCP as open source. The release had three parts: the specification and SDKs, local MCP server support in the Claude Desktop apps, and a repository of server implementations. Servers for Google Drive, Slack, GitHub, Git, Postgres and Puppeteer were available from the start. Block and Apollo were named as early adopters. Zed, Replit, Codeium and Sourcegraph were named among the development tools.

What Claude Desktop supported at that point was local servers, which run on the user's own computer.

2025: adoption, and remote connections

The revision of March 26, 2025 added two major features. One is Streamable HTTP, a transport for connections over the internet. The other is an authorization framework based on OAuth 2.1. Together they made the "remote MCP server" practical: a server that the provider runs, and that a user connects to with only a URL.

On the same day, OpenAI announced support for MCP. The Agents SDK supported it first, with the ChatGPT desktop app and the Responses API to follow. A company had adopted a standard made by its competitor, and MCP moved from one company's standard to an industry standard. On April 9, the CEO of Google DeepMind said that the Gemini models and SDK would support MCP. On May 19, at the Build developer conference, Microsoft and GitHub announced that they were joining the MCP steering committee.

The revision of June 18 let tools return structured data. It also added elicitation, which lets a server ask the user for more information. In September the official MCP Registry was announced. It is an index where public MCP servers are registered and found. By November it held close to two thousand entries.

On November 25, the first anniversary, specification 2025-11-25 was published. It added experimental tasks for long-running work, and an extensions framework for features that sit outside the core specification.

On December 9, Anthropic donated MCP to the Agentic AI Foundation (AAIF). The AAIF is a new fund under the Linux Foundation, co-founded by Anthropic, Block and OpenAI. Google, Microsoft, AWS, Cloudflare and Bloomberg support it. At that date, Anthropic reported more than 10,000 active public MCP servers and more than 97 million monthly SDK downloads across Python and TypeScript. MCP no longer belongs to one company. A neutral body manages it.

2026: the stateless protocol

Specification 2026-07-28, published on July 28, 2026, is the largest revision since remote connections arrived. The protocol became stateless. The section "What changed in 2026-07-28" below explains it.

According to the official blog, the main SDKs are now downloaded close to half a billion times a month.

How it works

The three participants

MCP has three participants: the host, the client and the server.

Name Role Example
Host The AI application that the user works in Claude Desktop, Visual Studio Code
Client A component inside the host that handles the connection to one server Built into the host
Server A program that provides data and tools The MCP server of an accounting service

The host creates one client for each server it connects to. Connect three servers, and the host holds three clients. A user sees only the host and the servers, and never deals with a client directly.

The three things a server provides

A server can provide three kinds of things to an AI application.

Kind What it is Example
Tools Functions that the AI model can execute Search invoices, add a calendar event
Resources Data for the AI to read The contents of a file, a database schema
Prompts Reusable instruction templates The steps to "summarise this month's expenses"

Of the three, mcpnavi lists the tools of each service, in the "Tools" field.

The two transports

A client and a server connect in one of two ways.

  • stdio: The server runs on the user's own computer and communicates over standard input and output. Nothing crosses the network. The user installs the server.
  • Streamable HTTP: The two sides communicate over HTTP. A user can connect over the internet to a server that the provider runs. OAuth is the recommended way to authorize.

The transport only decides the wire format. A user can also run a Streamable HTTP server in their own environment. Who runs the server is a separate fact. mcpnavi lists the two separately: the first as "Transport", the second as "Hosting".

What the messages look like

The client and the server exchange messages in a format called JSON-RPC 2.0. The flow is short.

  1. The client sends tools/list and receives the list of tools the server has.
  2. The host gives the list of tools to the AI model.
  3. The AI model picks a tool to match the user's request.
  4. The client sends tools/call. The server runs the tool and returns the result.
  5. The AI model writes its answer from the result.

To call a weather tool, the client sends a message like this one (shortened):

{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "weather_current",
    "arguments": { "location": "Tokyo", "units": "metric" }
  }
}

The server returns the result:

{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "resultType": "complete",
    "content": [{ "type": "text", "text": "Current weather in Tokyo: 24°C, clear" }]
  }
}

The list of tools holds a name, a description and an input definition (JSON Schema) for each tool. The AI model reads the description and decides which tool to use, and when. API documentation is written for people. A tool description is read by the AI model itself.

What changed in 2026-07-28

In the specifications up to 2025, a client first sent an initialize message to the server to set up the connection. The server kept state for each connection, called a session.

Specification 2026-07-28 removed that step. The client now sends the protocol version and its own capabilities with every request. The server handles each request on its own. A client can ask which versions and capabilities a server supports with server/discover.

This makes a server easier for a provider to run. A server that keeps no session can sit behind an ordinary load balancer, in any number of copies. The official blog says the change answers developers who wanted better reliability and scalability for their servers.

Tools, resources and prompts work as before. The specification also describes how to connect with servers and clients built for 2025-11-25 and earlier. Some features, such as Roots, Sampling and Logging, are now "deprecated". They stay in the specification, and become eligible for removal in the first revision released on or after 2027-07-28.

What to check before you connect

Once an MCP server is connected, the AI can read data and carry out actions. The specification asks implementers to follow these principles:

  • User consent and control: Users understand and agree to all data access and all operations.
  • Data privacy: A host does not pass user data to a server without the user's consent.
  • Tools: A tool can run arbitrary code, so treat it with caution. A host obtains the user's consent before it calls a tool.

The specification also says that the protocol itself cannot enforce these principles. The user decides which server to connect.

These facts help with that decision:

  • Who provides the service (Provider, Type, Japanese entity)
  • Who runs the server (Hosting)
  • How it authenticates (Authentication)
  • Which tools it provides (Tools)
  • When it was last updated (Last updated)

mcpnavi reads these fields for each service from public pages and lists them with the date they were last checked. A field that no public page states is shown as "Unknown". About the data explains what each field means and how it is checked.

Summary

  • MCP is a common standard that connects AI applications to outside data and tools.
  • Anthropic published it in November 2024. OpenAI, Google and Microsoft adopted it in 2025. A foundation under the Linux Foundation has managed it since December 2025.
  • It has three participants: host, client and server. A server provides tools, resources and prompts.
  • It has two transports: stdio and Streamable HTTP.
  • In specification 2026-07-28 the protocol became stateless, which makes servers easier to run.
