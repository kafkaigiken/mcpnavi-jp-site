MCP servers for Japanese services (November 2026 edition): telling official from unofficial by provider

An MCP server is a plugin that connects an AI agent to an outside service. More servers connect to Japanese services such as freee and kintone. However, a server named after a service is not always published by the company that runs the service.

This article covers ten Japanese services and sorts the MCP servers we could confirm on 9 November 2026 into official and unofficial. It also explains how to tell from the provider whether a server is official. For MCP itself, read the introduction to MCP.

Official and unofficial

In this article, "official" means an MCP server that the company running the service publishes under its own name. Every other server is "unofficial". The words only separate who publishes a server. They do not mean that an unofficial server is of lower quality.

A server from the company that runs the service has a clear owner for updates and a clear place to ask questions. An unofficial server comes from an individual or another company. Its updates can stop whenever the author chooses.

Three things to check about the provider

The provider's name

Check Provider on the MCPNavi detail page, and see whether it is the company that runs the service. A service name alone does not tell you that a server is official.

A Type of Company does not mean that the provider runs the service. For example, the Type of Sansan MCP (Supernova Tokyo) is Company, but its README states that it is not affiliated with Sansan, Inc.

Where the repository lives

For a server on GitHub, check who owns the repository. A repository under the company's own organization account, such as github.com/freee or github.com/nulab, can be treated as official. For a repository under a personal account, look in the README for a statement about whether the server is official.

The company's own announcements

Look for the server in the company's news releases, support pages and developer site. For a server you connect to by URL, the domain of the endpoint URL is another clue. freee's README warns readers not to enter any URL other than the official one.

The list as of November 2026

  • Unofficial: 15 servers across 8 services.
  • Services with no official server found: SmartHR and PayPay. Mercari is a different case, explained below.

What to check before you use an unofficial server

An unofficial server is published by someone other than the company that runs the service. Before you use one, check four things.

When it was last updated

Check the repository's history. When the API of the connected service changes, a server that is not updated can stop working.

What the API key can do

For a server that handles accounting, HR or payment data, limit the key to the permissions it needs. The API key has to be available where the server program runs. For the authentication methods, read how MCP servers authenticate.

The service's terms of use

Read the README to see how an unofficial server uses the service's API or web pages. Then check that this use follows the service's terms of use.

Hosting and transport

A Run it yourself server starts as a program on your own machine. Whether a client can connect depends on the hosting, the transport and the authentication together. Read the difference between remote and local MCP servers for details. To connect with only a URL, look in the list of services you can connect to with a URL alone.

Summary

  • A server named after a service is not always published by the company that runs it. Check three things: the provider, the owner of the repository and the company's own announcements.
  • On 9 November 2026, we could confirm 8 official servers across 7 services, and 15 unofficial servers across 8 services.
